# EIS AWS Inventory system (GENESIS-427822)

## What it is
Org-wide read-only AWS inventory. Pipeline: **Lambda** (container image, 40+ collector plugins) driven by **Step Functions** (`discover` → Map(`collect` per account) → `publish`), daily via EventBridge → **S3 snapshot** `s3://aws0iac-inventory-snapshots` (`latest/` + `runs/` + `athena/`) → **Athena** history (Glue db `aws0iac_inventory`) → **FastAPI+DuckDB dashboard** (Executive + Overview/Ask/Resources/Accounts/Drift/Health/Compliance/Recommendations/Topology/Teams, Cognito-gated) + **Prometheus exporter** (`eis_inventory_*` gauges) → Grafana. All Helm/ArgoCD on `aws0iacdeveks01`.

1. **`aws sso login --profile iac`** must be fresh. (See gotchas.)
2. **Lambda change** (plugins / lambda_function.py / IAM / SSM config): bump the `VERSION` constant, let CI build+push the image, then bump `image_tag` in `lower/dev/inventory/terraform.tfvars.json` and apply. Terraform no longer builds images — the `null_resource` local-exec docker build is gone.
3. **Dashboard/exporter change:** `docker buildx build --platform linux/amd64 --provenance=false -t <ecr>/aws0iac-inventory-dashboard:<v> -f dashboard/Dockerfile dashboard --push` (ECR login: `aws ecr get-login-password --region us-west-2 | docker login ...`), then bump the tag in chart `values.yaml`, commit chart, `kubectl -n argocd annotate application aws-inventory argocd.argoproj.io/refresh=hard --overwrite`.
4. **Run the pipeline:** `aws stepfunctions start-execution --state-machine-arn arn:aws:states:us-west-2:182399717428:stateMachine:project-resources-inventory --name <uniq>`; poll `describe-execution`; **0-failures gate** = collect Payload `failures:0`.
5. **Load the fresh snapshot now:** dashboard/exporter cache it (`REFRESH_SECONDS=3600`) → `kubectl -n inventory rollout restart deploy/inventory-dashboard deploy/inventory-exporter`.
6. **E2E:** Cognito login (script: GET `/`, submit the hosted-UI form with user `eramadan@eisgroup.com`, hit `/api/*`); exporter gauges via `kubectl exec <exporter-pod> -- python3 -c "import urllib.request;print(urllib.request.urlopen('http://localhost:9090/metrics')...)"`. ## Add a collector plugin
New `plugins/<svc>.py` returning `(resources, template)`; each resource `{name, stage, region, ...fields, tags}`. Wrap per-region in try/except (continue on error). For **gated** services emit a status row `{status:'not_enabled'|'access_denied'|'ok', ...}` instead of empty so the UI shows the right pill. Add read perms to `terraform/locals.tf inventory_actions`. The plugin flows into rows, plugin_stats, Athena, exporter, and the cross-account fan-out for free. **Local-test before deploy:** `AWS_PROFILE=iac python -c "import plugins.<svc> as m; print(m.list_resources({'regions':['us-west-2']},['us-west-2'],{},{}))"`.

## Add an in-cluster signal (ArgoCD / k8s) — NOT a lambda plugin
The collectors run in the **Lambda** (AWS side, no kube access), so anything that lives in the cluster (ArgoCD Application CRDs, pod metrics) CANNOT be a plugin. Read it in the **dashboard pod** (it's in-cluster): add the lib to `dashboard/requirements.txt` (`kubernetes`), a new `@app.get("/api/<x>")` using `kubernetes.config.load_incluster_config()` + `CustomObjectsApi`, guarded to return `{available:false}` on no-config/RBAC-deny, and a `ClusterRole`+binding for the `inventory-dashboard` SA in the chart (gated by a values toggle). Reference: Wave R1 `/api/argocd` reads `applications.argoproj.io` (group argoproj.io/v1alpha1, ns argocd) → `status.sync.status` + `status.health.status`. Frontend binds it via an `ensure<X>()` lazy-fetch like the other endpoints.

## Executive (manager) view + collectors that feed it
`dashboard/static/index.html` `renderExecutive()` = 5 Well-Architected pillar cards (Cost/Security/Governance/Reliability/Delivery) + an auto Risk Register. Each tile is `execTile({label,value,sub,tone,state})`; `state` ∈ ok|na|gated → renders value or "—"/"N/A"/"not enabled" (never $0/NaN). To add/bind a tile: write an `exec<X>()` helper that scans `model.rows` for the collector's `service`, then add a tile object to the right pillar array in `buildExec()` + (optionally) an `execRisks()` entry. Collectors feeding it: `securityhub_compliance` (CIS/FSBP %), `gitlab_dora` (DORA), `cloudwatch_slo` (uptime/MTTR), `guardduty`/`compute_optimizer` etc. **Activation deps for the gated tiles:** DORA → set the `lambda/project-resources-inventory-gitlab` secret (GITLAB_TOKEN) + `dora.projects` in the config; Uptime/MTTR → create CloudWatch SLO/composite alarms (eis-iac has none → tile reads "not enabled"); Compliance % → enable AWS Config (else CIS/FSBP show "not evaluable").

## Add another AWS account (multi-account) — the engine is ready
`_config_accounts()` reads an `accounts:` key (dict|list) from `inventory-config.yaml`; the SFN Map fans out per-account `role_arn`; `collect()` assumes it when it differs from the running account (`role_arn:""` = ambient eis-iac, no assume); **no ExternalId**. To onboard account N:
1. Create role **`eis-inventory-readonly`** in account N (read-only inline policy + trust = `arn:aws:iam::182399717428:role/project-resources-inventory`, NO ExternalId) — via an **Atlantis MR** to that account's `iac/projects/aws/<env>/terraform/lower/infra/core/` (pattern: `pto-reference/.../inventory_readonly.tf`, ref MR !41). Apply approval → mzivarts. **Make the MR pipeline green** (the `pre-commit` job runs `pre-commit run -a` REPO-WIDE): outputs go in `outputs.tf` WITH a `description`; checkov `#checkov:skip=CKV_AWS_355:<reason>` inline for the Resource:"*" read-only policy; and if ANY stage's `.terraform.lock.hcl` is stale (even one you didn't touch) the providers_lock hook fails your MR — regen with `terraform providers lock -platform=linux_amd64 -platform=darwin_amd64 -platform=linux_arm64 -platform=darwin_arm64` in that stage and commit the lock. Pre-flight locally: fmt, tflint, checkov, gitleaks. A green Atlantis plan ≠ green pipeline — both required. Details: memory `iac-mr-pipeline-green`.
2. eis-iac lambda role already has `sts:AssumeRole` on `arn:aws:iam::*:role/eis-inventory-readonly` (main.tf).

## Grafana dashboard-as-code
ConfigMap in the chart labeled `grafana_dashboard: "1"` (the kube-prometheus-stack Grafana sidecar runs `searchNamespace: ALL` → finds it in any ns); folder via annotation `eisgroup.com/dashboard-folder`. The template **globs** `grafana-dashboards/*.json` (`{{- range $path, $_ := .Files.Glob ... }}` keyed by `base $path`), so adding a board = one new file, no template edit.

Two boards today: `inventory.json` (KPI/posture — cost, coverage, security, freshness) and `inventory-resources.json` (resource-only view: account / region / service filters + a regex exclude, `uid: eis-aws-inventory-resources`).

**Grafana reads Thanos, not Prometheus** — the EIS overlay sets `thanos-query` as the default datasource. Query `observascope-oss-thanos-query.monitoring.svc.cluster.local:9090` when testing exprs.

**Test every panel expr against live Thanos before shipping**, from any in-cluster pod with python (the grafana container has none — use the dashboard pod):
```
kubectl -n inventory exec <dashboard-pod> -c dashboard -- python3 -c "..."   # /api/v1/query
```
Assert the **series count**, not just non-emptiness — see the honorLabels gotcha below and [[verify-shape-not-just-presence]]. Run the same exprs across several filter scenarios (all / one account / include-subset / exclude) and check the numbers move as expected; a filter that changes nothing is a no-op filter.

Verify the sidecar actually loaded it: `kubectl -n monitoring logs <grafana-pod> -c grafana-sc-dashboard | grep <name>`, and confirm the file landed with `kubectl -n monitoring exec <grafana-pod> -c grafana -- ls "/tmp/dashboards/EIS Inventory/"`. ## Gotchas (recurring)
- **`service` label collision (silent, cost weeks):** the exporter emits `service` = the AWS service, but Prometheus attaches its own `service` target label = the k8s Service name, and with default `honorLabels:false` the target wins — the real value is renamed `exported_service`. `sum by (service)` then returns ONE series named `inventory-exporter` holding the org total, and looks healthy. Fixed by `honorLabels: true` on the ServiceMonitor endpoint in `templates/exporter.yaml`. Safe here because `service` is the only collision (others are `account`/`region`/`plugin`; the exporter never emits `job`/`instance`) and no alert references `service`. Full write-up: [[prometheus-service-label-collision]].
- **Committed tfstate ≠ live state:** the legacy `terraform/terraform.tfstate` is checked into the app repo and goes stale the moment anyone deploys by hand (`aws lambda update-function-code`). Two verification agents independently reported the running Lambda version from it and were both wrong. Query AWS for what's running; use tfstate only for "what does Terraform think".
- **Stale comments outrank nothing — verify them:** `inventory-config.yaml` carried a comment saying pto-reference "goes green once eis-inventory-readonly exists (Atlantis MR)" long after MR !41 merged and the account was collecting 1219 rows. Two agents read the comment and declared the account broken. Check live behaviour before trusting an in-tree comment about live state.
- **TF provider vs SSO cache:** when the `iac` SSO token expires the AWS provider errors `SSO session expired` even if the CLI works. Fix = fresh `aws sso login --profile iac`, then plain `terraform apply` (provider + the null_resource's CLI ECR login both work). Do NOT pass `-var aws_profile=""` (breaks the null_resource's `export AWS_PROFILE=`).
- **Confluence/wiki + Jira are VPN-gated:** off-VPN the Jira PAT 302-redirects to SSO and the internal wiki 503s. `_publish_confluence` + `_publish_digest` are **best-effort** (wrapped) so a wiki outage never fails the SFN — the S3 snapshot promotes BEFORE the publish. Post Jira (REST v2, `JIRA_TOKEN` from ~/.zshrc) only when on-VPN.
- **Snapshot cache:** dashboard/exporter read `latest/` every `REFRESH_SECONDS` (3600) → `rollout restart` to see a just-finished run immediately. Note the dashboard pod loads the snapshot at startup, so an ArgoCD rollout that finishes BEFORE the SFN run leaves the pod on the old snapshot → restart again after the run.
- **Service name = plugin filename:** a row's `service` is the plugin's filename. The frontend/exec tiles + manager_facts `DERIVED_SERVICES` must filter on that exact name. (Wave R bug: `securityhub_compliance.py` → service `securityhub_compliance`, but the tile filtered `compliance_standards` → showed N/A despite data. Keep the plugin filename and the frontend filter identical, and add new collector names to `DERIVED_SERVICES`/`EXEC_DERIVED`.)
- **Bedrock NL-query (`/api/ask`):** Anthropic models are account-use-case-gated → uses **Amazon Nova Pro** (`us.amazon.nova-pro-v1:0`). Backend hard-validates the generated SQL is a single read-only SELECT against table `r` before executing + one-shot auto-repair.
- **Security Hub compliance needs AWS Config ON:** with Config off, standards can't evaluate (only `Config.1` fails) → the scorecard reports `evaluable:false` "enable AWS Config", not 0%.
- **Lambda f-strings:** `rds.py:~267` uses a py3.12 f-string with backslashes — `py_compile` FAILS under a local **py3.9** but is fine on the 3.12 runtime; don't "fix" it. Compile with `python3.12 -m py_compile` locally (CI uses `python:3.12-slim`, so it never sees this).
- **Lambda is a container image, not a zip:** `update-function-code` needs `--image-uri`, and the image must be a **single manifest** — build with `--provenance=false --sbom=false` or Lambda rejects it with "image manifest ... not supported" (buildx defaults to a manifest list).
- **Jira/wiki bypass:** the cloud Atlassian MCP can't reach the on-prem `jira.eisgroup.com`/`wiki.eisgroup.com` — use REST v2 + bearer PAT (see [[jira-eisgroup-datacenter-access]]).
