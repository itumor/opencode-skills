01What this directory is

The root is not a git repo. It is a workspace holding every project of the GitLab group iac on the VPN-only server sfo-cvdevopsgit01.eqxdev.exigengroup.com, cloned by clone_all.sh into a matching folder layout. Each folder with a .git is its own project, with its own MRs and CI.

It is the infrastructure-as-code estate for EIS OneSuite client environments on AWS. The pieces fit together like this:

  • Terraform modules (eis-*) wrap AWS resources.
  • Copier templates generate per-client Terraform, Ansible and ArgoCD trees.
  • Atlantis plans and applies Terraform from MRs.
  • An ArgoCD hub pushes Helm components to 10 EKS clusters.
  • Ansible configures the toolchain VMs.
  • A shared network hub carries TGW, egress and VPN.

Around the repos sits a working layer of ticket notes (docs/), parallel git worktrees (.worktrees/), memory stores (.remember, .memsearch) and a Claude Code harness (.claude, a symlink to ~/.claude/harness/iac) that enforces the MR and apply gates.

Six templates generate most repos. The Terraform and Ansible templates use [[ ]] / [% %] Jinja markers so HCL and Ansible {{ }} pass through. Answers are recorded in .copier-answers.yml, and project-specific code lives only in *_custom.tf.

11Change workflow and gates

  1. Branch in the nested repo, or in a worktree under .worktrees/ (never in the shared checkout). Commit as type(scope): KEY-N - msg with KEY one of COEXT, GENESIS, NOJIRA or EISSAASDEV, and no ! in some eis-* repos.
  2. Pre-push: commit-lint and pre-commit on changed files (hook), and the repo's real CI via gitlab-ci-local (manual rule). verify-iac-changes runs before claiming done.
  3. Open the MR with reviewer eramadan. Atlantis autoplans and the PR-Agent bot posts a Reviewer Guide and Code Suggestions. Each item is fixed or answered.
  4. Read the plan: tag each change MR-caused or environment-carried, and note any destroys or replacements.
  5. Apply is proposed only when the MR is Approved on the current head SHA. The handoff must carry three lines: Approval:, Cost: (Jira cost approval for priced resources) and Disruption: NONE|BLIP|OUTAGE. The user runs atlantis apply.
  6. Merge only via mr-merge-gate.py, which runs 8 checks: not draft, no conflicts, approved by a non-author, plan and apply on the current head, no later pending plan, pipeline green, mergeable. Non-Atlantis repos such as argocd are merged by the user.

18Glossary

Atlantis
Runs Terraform from MRs. Plan is automatic; atlantis apply is always typed by the user.
Copier
Template engine behind client, POC, hub, cluster and Ansible repos. It tracks answers in .copier-answers.yml.
eis-* module
EIS Terraform wrapper module, pinned by git tag.
lower / upper
Environment tiers: lower = infra/dev/test, upper = share/stage/prod, often a separate account and region.
bootstrap / core / services
The three Terraform states per stage: state bucket and roles, then network, then workloads.
Hub / satellite
The hub region owns egress, S2S VPN and the TGW. Satellites attach and never own egress.
pref-dev
aws0prefdeveks01, the ArgoCD playground cluster in the pto-reference account.
Playground-first
Change components-playground and prove it on pref-dev before components.
ESO
External Secrets Operator, which syncs AWS Secrets Manager or Vault into Kubernetes.
Observascope
EIS observability stack components (eis, oss, logging, exporters).
P0–P8
OneSuite onboarding phases: prereqs, vend, scaffold, infra, dev, Ansible, ArgoCD, handoff, E2E.
Account vending
Create the account, place it in the OU and bootstrap it with a StackSet (state bucket + Atlantis roles).
PR-Agent
Self-hosted LLM MR reviewer on the hub, active on every repo in group iac.
superagent
Headless Claude workers driven by Jira tickets, with an iac profile in the harness.
Cockpit
Local UI at 127.0.0.1:8765. Each Jira write needs a user click plus a macOS dialog.
Handoff gate
Stop hook requiring Approval, Cost and Disruption lines before any apply handoff.
CAA
Credit Agricole, the reference client project.

How this was built. On 2026-11-05, four read-only agents each surveyed one area (Terraform, ArgoCD + Ansible, solutions + harness, non-repo content + git state). Headline counts were re-checked on disk with ls and find. No fetch, AWS call or GitLab call was made, and no secret files were opened. Tags, branches and "behind" counts reflect local clones. Items the agents could not confirm are left out or flagged as unverified.
